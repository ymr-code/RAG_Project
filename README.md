# ARVELES RAG — Local Offline Q&A Assistant

A fully offline Retrieval-Augmented Generation (RAG) assistant that answers questions about the **ARVELES 25 mg** package leaflet, built with [Microsoft Foundry Local](https://github.com/microsoft/Foundry-Local). Embedding, retrieval, and generation all run locally on-device, with no cloud calls and no internet dependency after the models are downloaded.

Built as a hands-on learning project to understand the RAG pattern end to end: chunking, embeddings, vector similarity search, and grounded generation with a small local LLM.

> ⚠️ **Disclaimer:** This is an experimental student project, not a medical product. It's a first attempt at building a RAG pipeline and is meant for demonstration only — please don't use it for real medical decisions. Always consult a doctor or pharmacist and refer to the official package leaflet.

## How it works

```
User question
      │
      ▼
Embed question (qwen3-embedding-0.6b)
      │
      ▼
Compare against chunk embeddings in SQLite (cosine similarity)
      │
      ▼
Take top-3 most relevant chunks
      │
      ▼
Send chunks + question to Phi-3.5 Mini with a grounding system prompt
      │
      ▼
Answer (restricted to the provided context only)
```

The knowledge base is the ARVELES leaflet, translated to English and structured as semantically-chunked HTML (`arveles_leaflet_en.html`), split by `<h3>` and, where relevant, `<h4>` sub-headings so each topic (e.g. a side-effect frequency tier or a drug-interaction risk level) stays its own retrievable chunk.

## Tech stack

- **[Foundry Local](https://github.com/microsoft/Foundry-Local)** — on-device model runtime
- **qwen3-embedding-0.6b** — embedding model
- **Phi-3.5 Mini** — chat/generation model
- **SQLite** — local storage for chunks + embeddings
- **BeautifulSoup4** — HTML parsing/chunking

## Project structure

```
.
├── arveles_leaflet_en.html   # source document, pre-chunked with semantic HTML tags
├── ingest.py                 # parses HTML -> chunks -> embeddings -> SQLite
├── retrieve.py                # standalone retrieval test (no LLM call)
├── answer.py                  # full RAG pipeline (retrieval + generation)
├── check_db.py                # sanity check of arveles.db contents
├── test_embedding.py          # smoke test for the embedding model
└── arveles.db                 # generated by ingest.py (not committed)
```

## Setup

```
python -m venv venv
venv\Scripts\activate            # Windows
source venv/bin/activate         # macOS/Linux

python -m pip install foundry-local-sdk openai beautifulsoup4
```

Models (`qwen3-embedding-0.6b`, `phi-3.5-mini`) download automatically on first run via Foundry Local.

## Usage

```
python ingest.py     # build/rebuild the knowledge base
python answer.py     # ask questions
```

Optional helper scripts: `retrieve.py` (test retrieval only, no LLM) and `check_db.py` (inspect stored chunks).

## Notes

As a first RAG project, this is still a work in progress — some questions get better answers than others, and there's plenty of room to improve chunking and retrieval further. Suggestions welcome.
